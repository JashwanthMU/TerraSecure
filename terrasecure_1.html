The Problem

Detection was never
the issue. Noise was.

In 2019, Capital One's security team had a Checkov-style scanner running. It flagged the issue. It was buried under 147 other alerts. The team ignored it. 100 million records got stolen. $190 million in fines.

The problem wasn't detection. The problem was noise. Every misconfiguration looked equally urgent. There was no risk score, no business context, no explanation of what would actually get exploited first. That is exactly what TerraSecure is built to fix.

The Solution

ML + Rules + AI.
Three layers of detection.

TerraSecure is an open-source ML-powered Terraform security scanner. Instead of pattern-matching rules alone, it uses a machine learning model trained on 265 real breach examples — Capital One, Uber, Tesla, MongoDB — and scores every resource with a risk probability from 0.0 to 1.0. It then calls AWS Bedrock (Claude 3 Haiku) to explain why something is dangerous, what the business impact is — financial, regulatory, reputational — and provides the exact Terraform fix. Not just a rule ID. A working code change.

📂

Input & Parsing

Accepts Terraform files, HCL configurations, and modules. The HCL parser extracts all resource blocks and passes them to both the rule engine and ML feature extractor simultaneously.

HCL Parser Resource Extractor
🧠

Detection Engine

Two parallel detection paths: a rule engine running 50+ hand-crafted security patterns, and an XGBoost ML model that extracts 50 security features per resource and outputs a 0.0–1.0 risk score. Both paths contribute to the final finding.

XGBoost 50 Features 50+ Rules
✨

AI Analysis Layer

Each finding is enriched by AWS Bedrock (Claude 3 Haiku) with business impact analysis, a real-world attack scenario, and a specific code fix. A response cache delivers 90% cost savings on repeated findings across repositories.

Claude 3 Haiku 90% cache savings
📊

Multi-Format Output

Human-readable text for local runs, structured JSON for automation pipelines, and SARIF 2.1.0 for native GitHub Security tab integration — full code scanning alerts, PR comments, and security dashboard metrics.

SARIF 2.1.0 JSON · Text
🔗

Integration Layer

Deployed as a GitHub Action on the Marketplace, a Docker container on GHCR, or run directly from the CLI. Works offline — ML inference requires no internet connection, only AI enrichment calls Bedrock.

GitHub Actions Docker CLI

Request Flow

Resource → detect → ML score → AI enrich (cache check first) → enhanced finding → format and output. Each resource is processed independently in under 100ms. AI enrichment adds context only on cache miss.

<100ms/resource Cache-first AI

Violations → Findings

The ML model outputs a continuous risk score from 0.0 to 1.0 and a confidence value. Resources scoring above the 0.5 threshold are flagged as risky.

The final finding includes: severity, ML risk score, business impact, real-world attack scenario, regulatory implications, and a working Terraform code fix. Output in Text, JSON, or SARIF 2.1.0.

CRITICAL S3 bucket publicly accessible — s3_block_public_access_disabled ML 0.95
aws_s3_bucket.customer_data · storage.tf:12

Public ACL exposes all bucket contents to unauthenticated internet traffic. Automated scanning tools like S3Scanner and bucket-stream can enumerate all objects within minutes of deployment.

↳ Capital One 2019 — 100M records exposed via this exact misconfiguration — $190M in fines
✓ Fix: acl="private" + block_public_acls=true + server_side_encryption_configuration { rule { apply_server_side_encryption_by_default { sse_algorithm = "AES256" } } }
CRITICAL SSH port 22 open to 0.0.0.0/0 — open_ssh_port_22 ML 0.91
aws_security_group.web · network.tf:8

Port 22 exposed to the entire internet enables brute-force and credential stuffing attacks within minutes of deployment. Violates CIS AWS Benchmark 5.2.

↳ Uber 2016 — credential exposure led to 57M account breach
✓ Fix: restrict cidr_blocks to your VPN CIDR or use AWS Systems Manager Session Manager instead
HIGH MFA not enforced on IAM — mfa_not_enabled ML 0.82
aws_iam_user.admin · iam.tf:5

IAM users without MFA enforcement are vulnerable to credential theft. A single compromised password grants full account access. Violates SOC 2 CC6.1 and PCI-DSS 8.3.

↳ Compliance risk: SOC 2 Type II failure · PCI-DSS audit failure
✓ Fix: Create aws_iam_policy enforcing MFA with Condition "aws:MultiFactorAuthPresent" = "true"

Scan any directory with a single docker run. Works in air-gapped environments. ML inference runs entirely offline.

# Scan + SARIF output
docker run --rm \
  -v $(pwd):/scan \

  /scan --format sarif
CLI

Command Line

Run locally before committing. Supports text for humans, JSON for pipelines, and SARIF for GitHub Security integration.

# Local scan
python src/cli.py infrastructure/ \
  --format sarif \
  --output results.sarif \
  --fail-on high
▶Quick Start — Local Install
# Clone and install
$ git clone https://github.com/JashwanthMU/TerraSecure.git && cd TerraSecure
$ pip install -r requirements.txt
# Scan your infrastructure directory
$ python src/cli.py infrastructure/ --format sarif --output results.sarif
# Try the bundled vulnerable example to see it in action
$ python src/cli.py examples/vulnerable --fail-on critical
